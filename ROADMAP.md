# Roadmap - ranked by impact/effort (July 2026 scout)

## 1. Ship the missing external-validation module + calibration dashboard (productize the thesis experiment)  (small effort)

**Impact:** This is currently a broken headline feature: ui/widgets/active_panel_widget.py:6099 imports `analysis.metric_validation.MetricValidator` (SSIM/PSNR/MSE/LPIPS + AI-score validation + correlation stats), but analysis/metric_validation.py does NOT exist in the repo — every user hits 'Metric validation unavailable'. Fixing it ships the exact thing the SIGGRAPH poster is about (self-score vs objective score), and a dashboard makes the plugin the only tool that shows users when the AI is lying about its own quality — a unique differentiator no competitor (Intangible, Cybever, Ludus) has.

Recover metric_validation.py from the thesis working tree (pythonwithBatchStorybaord) and commit it to Content/Python/analysis/. The data plumbing already exists: `_validate_ai_score_with_objective_metrics()` stores last_objective_metrics/last_validation_result, and `_update_multi_model_csv()` (active_panel_widget.py:6845) already writes per-run CSVs. Add a `ui/widgets/calibration_dashboard.py` Qt tab that plots self-score vs composite objective score per iteration from that CSV (matplotlib-to-PNG or a simple QPainter scatter), with the running correlation r/p already computed by `calculate_correlation_statistics()`.

## 2. One-click animatic: Movie Render Queue render of the master sequence to MP4  (medium effort)

**Impact:** The deliverable of previz IS a watchable animatic — Previs Pro 3 ships MP4-with-audio animatic export as a headline feature (cgchannel.com, previspro.com), so this is table stakes. The plugin already builds per-panel shot sequences with camera cut tracks and a master sequence with per-panel durations (core/sequence_generator.py: create_sequence, create_master_sequence), so 'storyboard in → video out' is one API call away and is the single best demo/adoption hook for previz artists and indie filmmakers.

New core/animatic_renderer.py: use `unreal.MoviePipelineQueueSubsystem` to enqueue the master sequence produced by SequenceGenerator.create_master_sequence(), attach a MoviePipelineOutputSetting (mp4 via Apple ProRes/ffmpeg CLI encoder node or PNG sequence + bundled ffmpeg), and execute with MoviePipelinePIEExecutor — Epic ships a reference script (Engine/Plugins/.../MoviePipelineEditorExample.py) and documents command-line MRQ rendering (dev.epicgames.com 'Command Line Rendering With Unreal Engine Movie Render Queue'). Wire a 'Render Animatic' button into ui/main_window.py next to the existing batch buttons; per-panel durations already flow from `on_panel_duration_changed` (active_panel_widget.py:965) and settings' default_panel_duration. Note sequence_generator.py hardcodes fps=30 at line 111 — lift to a setting while in there.

## 3. Per-run cost estimator + live token/cost strip in the UI  (small effort)

**Impact:** API cost anxiety is the top stated blocker for indie/hackathon users (README already warns ~$0.01–0.05/panel). All the data exists but is invisible: providers track total_cost, cache_savings, per-call tokens (core/ai_providers/claude_provider.py lines 279–298) and even have `get_cost_estimate()` — yet cost only goes to unreal.log (active_panel_widget.py:3917, :4944). Showing 'this 6-panel board at 10 iterations ≈ $1.80' before the run, and a live meter during it, converts fear into trust.

Add a QLabel cost strip to ActivePanelWidget next to the existing `match_progress` QProgressBar (active_panel_widget.py:807): pre-run estimate = num_panels × max_iterations × provider.get_cost_estimate(num_images=8) (7 captures + storyboard), updated live from the `tokens`/`cost` dict every provider response already returns. Surface cache savings ('saved $0.42 via prompt caching') from claude_provider's total_cache_savings — it's already computed. Extend utils/token_counter.py (currently OpenAI/tiktoken-only) with the Anthropic per-model price table so estimates work for both providers.

## 4. Downloadable sample UE project + genre starter asset libraries  (small effort)

**Impact:** Highest-leverage onboarding for the hackathon this week: current setup requires cloning into Plugins/, a C++ build (VS2022), pip-installing into UE's bundled Python, and hand-copying samples/asset_library.sample.json. A ready-made project zip (plugin pre-built, sample library pre-wired, 6 panels pre-imported, one scene pre-generated) turns 30–60 min of setup into 5, which for a 2-day hackathon is the difference between being used and being skipped. Genre libraries (interior-drama, sci-fi, exterior-action) built from free Fab/Quixel packs multiply first-run quality since the AI can only position assets it can match (README 'Asset library required' limitation).

Package a minimal UE 5.6 project with the plugin as a GitHub Release artifact (CI already exists in .github/workflows). Extend samples/asset_library.sample.json into 2–3 genre variants whose asset_path entries point at free Fab packs the README links for manual install (no Fab API needed — see notes), keeping the /Engine/BasicShapes fallback (core/asset_matcher.py get_fallback_asset) as the zero-download path. Add a 'Load Sample Show' button in ui/widgets/show_manager.py that copies the chosen library + sample panels into the show directory structure ShowsManager already manages.

## 5. Headless/overnight batch mode (CLI, no UI)  (large effort)

**Impact:** The iterative loop takes minutes per panel (up to 20 iterations × 7 captures × extended-thinking calls) — the natural workflow is 'queue the whole board, come back in the morning', which no current mode supports: batch_generate_all_panels (active_panel_widget.py:6363) literally walks the Qt widget tree to find MainWindow, so batch requires the editor open with the window up. Epic documents headless editor Python via `-run=pythonscript` and `-ExecutePythonScript` (dev.epicgames.com 'Scripting the Unreal Editor Using Python'), and this also unlocks CI-style research sweeps for the calibration experiments.

Extract the orchestration from ActivePanelWidget into a UI-free core/batch_runner.py that takes (show, episode, provider, max_iterations) and drives PanelAnalyzer.batch_analyze → SceneBuilder.build_scene → the capture/adjust loop, replacing QTimer-based sequencing (_cleanup_scout_delayed etc.) with unreal.register_slate_post_tick_callback state machines. Entry point: `UnrealEditor-Cmd.exe Project.uproject -ExecutePythonScript=.../batch_runner.py -RenderOffscreen`, writing results + metrics CSV to the show directory. Risk to spike first: the scout-camera viewport-pilot capture path may not work offscreen (UNVERIFIED) — fall back to SceneCapture2D render targets, which ai_vision/viewport_capture_ultra_safe.py already flirts with.

## 6. Semantic asset matching via embeddings (replace difflib fuzzy match)  (medium effort)

**Impact:** Asset matching is the quality ceiling after positioning: core/asset_matcher.py:229 uses difflib.SequenceMatcher character similarity, so 'wooden dining table' will never find 'SM_Furniture_Deluxe_01' and falls back to a cube. Embedding the AI's object description against asset names + the show library's existing 'description' fields (already in samples/asset_library.sample.json schema) makes matching work the way users assume an 'AI plugin' should — Cybever explicitly markets 'retrieval' as one of its three pillars.

In AssetMatcher.build_asset_cache(), compute embeddings for each asset's name+description once and cache to ~/.storyboard_to_3d/embeddings.json; at query time replace _fuzzy_match with cosine similarity. Use OpenAI text-embedding-3-small (~$0.02/1M tokens, negligible per-library) via the existing api/ client, with a local fallback through the same out-of-process pattern the repo already uses to dodge UE DLL conflicts (pytorch_server.py subprocess — add an /embed endpoint using sentence-transformers). Keep difflib as the no-API-key fallback tier in find_best_match's priority chain.

## 7. Storyboarder (.storyboarder) and ComfyUI folder import  (small effort)

**Impact:** Free inbound pipeline from the most popular free storyboard tool: Wonder Unit's Storyboarder is open source and its .storyboarder file is documented JSON — boards array with PNG paths, per-board duration in milliseconds, fps (github.com/wonderunit/storyboarder/wiki/Storyboarder-File-Format). Those durations map 1:1 onto the plugin's per-panel duration → Sequencer timing, so an imported board becomes a correctly-timed animatic with zero manual entry. A ComfyUI 'import folder of generated panels' path is the same code with a glob.

Add core/importers/storyboarder_importer.py: parse the JSON, resolve board-{n}-{uid}.png paths from the images/ sibling folder, create panels via the existing episode/panel structures in core/episodes_manager.py, and set each panel's duration from `boards[].duration` (ms → seconds) so it flows through on_panel_duration_changed → SequenceGenerator.create_sequence. Register it in the Import Panels dialog in ui/main_window.py as a file-type filter alongside plain images; ComfyUI import is the images-only degenerate case with default_panel_duration.

## 8. Iteration progress UI with live score graph and cancel button  (small effort)

**Impact:** A 10–20-iteration run is minutes of apparent freeze today: progress lives in unreal.log and an ASCII chart (_generate_ascii_graph, active_panel_widget.py:5166); the only QProgressDialogs are for one-shot analysis (line 5538). A visible 'iteration 7/20, score 62→78, $0.34 spent, [Stop & keep best]' panel is what makes people trust the loop enough to use it on real work — and it is demo-critical for SIGGRAPH week.

Add an IterationProgressWidget (new file ui/widgets/iteration_progress.py) fed from _start_next_iteration (active_panel_widget.py:5014) and _record_iteration_metrics (:5982), which already hold the scores list, iteration count, and per-iteration cost. Render the score history as a QPainter sparkline (replacing the ASCII graph), plus provider name, cache-hit indicator, and a cancel flag the iteration state machine checks between capture steps. Checkpointing already exists (_on_checkpointing_changed, :984) so 'stop & keep best iteration' is mostly wiring.

## 9. USD export of the generated scene (and sequence)  (medium effort)

**Impact:** Makes the output portable to the rest of the previz ecosystem — Houdini, Maya, Omniverse, and studio USD pipelines — instead of trapping results inside one UE project; competitors are weak here (Intangible advertises no concrete export formats on its film page — UNVERIFIED what it supports; Previs Pro only ingests glTF). UE already ships the exporter: unreal.LevelExporterUSDOptions and LevelSequenceExporterUsdOptions are in the Python API (dev.epicgames.com Python API docs), so this is high interop credibility per unit effort.

Add core/usd_exporter.py that enables the USDImporter/Exporter plugin, builds an AssetExportTask with LevelExporterUSDOptions for the built level, and a second task using LevelSequenceExporterUsdOptions for the shot's LevelSequence so camera animation survives. Expose 'Export scene as USD' per panel and 'Export show as USD' in ui/main_window.py; write next to the show directory managed by core/shows_manager.py. Caveat: spawnables live in the sequence, not the level — may need to convert to possessables or bake transforms before export (spawnable-vs-possessable handling already exists in core/scene_builder.py _create_spawnable_from_config).

Roughly 60% built already: _update_multi_model_csv (active_panel_widget.py:6845), show_model_comparison (:6963) and export_combined_comparison (:6971) exist; what's missing is orchestration and a side-by-side visual.

Add a 'Compare Providers' action that runs the same panel through provider A then B via core/ai_providers/provider_factory.py, saving/restoring initial actor transforms with the existing _capture_actor_transforms/_restore_actor_transforms (active_panel_widget.py:4052/:4137) so both runs start identically. Render a results dialog showing each run's hero capture, final self-score vs objective score (from MetricValidator), iterations-to-converge, and total cost — all fields the multi-model CSV already records. Structured outputs (PositioningAnalysis Pydantic model + sanitize_schema_for_openai, active_panel_widget.py:117–247) already normalize both providers' responses, so comparison is apples-to-apples.
